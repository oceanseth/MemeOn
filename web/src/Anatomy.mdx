# UI anatomy

Five tiers. Everything below **Views** is a pure function of its props.

`src/` is organized as atoms → molecules → organisms → screens → views.
Everything below `views/` is a pure function of props: no state hooks, no
stores, no fetch. State lives in `hooks/` (one `useXScreen()` per screen,
exporting `XScreenModel`) and `stores/`. Every component has a sibling
`*.stories.tsx` titled `"<Tier>/<Name>"`. Read this file before adding
or moving a component. `cd web && node scripts/check-tiers.mjs src` must pass.

| Tier | Folder | What lives there | Owns state? |
|---|---|---|---|
| **Atoms** | `src/atoms/` | `MemeCard` (plus `tierClasses`) | No |
| **Molecules** | `src/molecules/` | `ConfirmDialog`, `SortChips`, `GiftDialog`, `QuestBar`, `AlertsBell` | No |
| **Organisms** | `src/organisms/` | `AppShell` (slots), `MemeplexPanel` | No |
| **Screens** | `src/screens/` | One model object per route/chrome surface | No |
| **Views** | `src/views/` | Engine wired to screen; `observer` wrap; `AppView` is the route switch | Via hooks |

## Composition tree

```
main.tsx ── StoresProvider + AuthRuntime + BrowserRouter
└─ App.tsx (re-export) ── AppView
   ├─ RequireAuth · BinderOwnRedirect · BinderRoute · ProfileRoute · MemeDetailRoute · LegacyMemeRedirect
   └─ AppShellView ── useAppShellScreen → AppShellScreen
      ├─ AppShell
      │   ├─ QuestBar
      │   └─ AlertsBell
      └─ Routes
         ├─ LandingView ── useLandingScreen → LandingScreen ── HeroVideo (legacy, via hook)
         ├─ CreateMemeView ── useCreateMemeScreen → CreateMemeScreen
         ├─ MarketplaceView ── useMarketplaceScreen → MarketplaceScreen ── SortChips · MemeCard*
         ├─ MemeDetailView ── useMemeDetailScreen → MemeDetailScreen ── ConfirmDialog · MemeplexPanel ── MemeCard*
         ├─ TradesView ── useTradesScreen → TradesScreen
         ├─ FriendsView ── useFriendsScreen → FriendsScreen ── GiftDialog
         ├─ BinderView ── useBinderScreen → BinderScreen ── SortChips · MemeCard*
         ├─ ProfileView ── useProfileScreen → ProfileScreen ── MemeCard*

```

## Where state lives

| Engine | Holds | Read by |
|---|---|---|
| `stores/authMachine` + `AuthStore` | session: `idle → loading → ready \| unauthenticated` | `useAuth`, `useAuthRuntime`, screen hooks |
| `stores/createStores` + `StoresContext` | app store bag; stories get a fresh bag | views via hooks |
| `stores/*Machine.ts` (one per flow) | XState source of truth for that screen | matching `useXScreen()` |
| `hooks/useXScreen.ts` | view-model: snapshot + callbacks + derived flags | matching `XView` → `XScreen` |
| `hooks/useAuth.ts` | `user`, `loading`, `refresh`, `logout` | `RequireAuth`, chrome, screens |
| `lib/presence.ts` | Firebase online flag | `useAuthRuntime`, Friends watch |

## Rules

- Below Views, no hooks and no state library.
- The model type is exported by the hook, not the screen.
- A new state starts as a Screen story.
- Every component has a sibling `*.stories.tsx` titled `"<Tier>/<Name>"`.
- Views opt out of autodocs (`!autodocs`) and wrap with `MemoryRouter`.
- Do not put `observer` or `useState` below `views/`.
- No redesign while moving: class names and markup stay.

## Talking about it

Name the tier and the piece: *"the `MemeCard` atom"*, *"the `GiftDialog` molecule"*,
*"the `CreateMemeScreen` › `Error` story"*, *"`useMarketplaceScreen` should hide the grid on empty"*.

## Listed legacy

These stay outside the tiers on purpose. `npm run check-tiers` passes them with
`--legacy components,pages,context,stories`. Running the checker with no flags
still reports files in those leftover folders; that is expected until they are
deleted or moved.

| Path | Why it stays |
|---|---|
| `components/HeroVideo.tsx` (+ `.css`) | Imperative media element; Landing hook injects it as `hero` |
| `pages/AuthCallback.tsx` | OAuth redirect ritual |
| `pages/MobileAuthForward.tsx` | Deep-link forward ritual |
| `lib/extractPoster.ts` | Canvas/video frame grab (root-importable; not a checker target) |
| `lib/presence.ts` + AuthRuntime/Friends watch | Firebase presence |
| `context/AuthContext.tsx` | Re-export of `useAuth` |
| `src/stories/` | Storybook CLI examples (Button/Header/Page) |

`App.ts` is a re-export of `AppView` only (`main.tsx` imports `./App`). A `.tsx` re-export at `src/` would still be a stray to the checker. Routing adapters live in `views/AppView.tsx`. The two leftover auth pages are imported via `lib/legacyAuthPages.ts` so `views/` does not import `pages/` directly.
