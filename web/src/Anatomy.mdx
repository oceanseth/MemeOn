# UI anatomy

Five tiers. Everything below **Views** is a pure function of its props.

`src/` is organized as atoms → molecules → organisms → screens → views.
Everything below `views/` is a pure function of props: no state hooks, no
stores, no fetch. State lives in `hooks/` (one `useXScreen()` per screen,
exporting `XScreenModel`) and `stores/`. Every component has a sibling
`*.stories.tsx` titled `"<Tier>/<Name>"`. Read this file before adding
or moving a component. `pnpm --filter web run check-tiers` runs recursively and must pass;
`pnpm run build` runs it before type-checking and Vite.

| Tier | Folder | What lives there | Owns state? |
|---|---|---|---|
| **Atoms** | `src/atoms/` | `Alert`, `AlertDialog`, `Avatar`, `Badge`, `Button`, `Card`, `Checkbox`, `Collapsible`, `Dialog`, `DropdownMenu`, `Empty` (+ `PageState`), `Field`, `FileDrop`, `FoilCard` (+ `FoilMedia`), `Heading`, `Icon`, `InlineLink`, `Input`, `InputGroup`, `Item`, `Label`, `LiveRegion`, `PageContainer`, `PageHead`, `Popover`, `PortalAnchor`, `Progress`, `Select`, `Separator`, `Skeleton`, `Spinner`, `Tabs`, `Textarea`, `TierChip`, `Toggle`, `ToggleGroup`, `Toolbar` | No |
| **Molecules** | `src/molecules/` | `AlertsBell`, `AvatarMenu`, `ConfirmDialog`, `DialogFrame`, `FaqItem`, `GiftDialog`, `HeroVideo`, `LegalDocument`, `QuestBar`, `SideSummary`, `SortChips`, `ThemeControl`, `MemeCard`, `TradeCard` (`give`/`get`, not `offer`/`ask`) | No |
| **Organisms** | `src/organisms/` | `AppShell` (slots `nav` / `headerEnd` / `bottomNav`), `MemeplexPanel`, the `nav-item.tsx` links `NavPill` / `TabItem` / `FooterLink` | No |
| **Screens** | `src/screens/` | One model object per route/chrome surface | No |
| **Views** | `src/views/` | Engine wired to screen; `observer` wrap; `AppView` is the route switch | Via hooks |

Beside the tiers, four folders are the engine side:

| Folder | What lives there |
|---|---|
| `src/copy/` | **Every user-facing string**, one plain-data module per surface (`settings.ts`, …) plus `shared.ts` for labels that recur. Keys name the role (`intro`, `account.logOut`), never the content; dynamic strings are small pure functions (`account.name(user.name)`, `` shown: (n) => `${plural(n, 'card')} shown` ``). `copy/` imports nothing but `copy/` and the two formatting helpers `lib/plural` and `lib/braincells`, so a noun stays beside its sentence. Hooks and `lib/*Model.ts` builders read it; tests and stories assert **through the same constant**, so a copy change touches one file. Tier components never import it — strings reach them as props. |
| `src/hooks/` | One `useXScreen()` per screen (exports `XScreenModel`), plus `useAuth`, `useTheme`, `useProjectedActor`, `useDocumentTitle`, `useMountEffect` |
| `src/stores/` | XState machines (`*Machine.ts`), the MobX `AuthStore` / `ThemeStore`, `createStores` + `StoresContext` |
| `src/lib/` | Everything with no React tree: the API client, auth, presence, formatting (`braincells`, `plural`), `cn()`, class maps (`lib/binderChrome.ts`; same family as `cn()` / `atoms/foil.ts` `tierFrameClasses`), the imperative `cardMedia`, and the **model builders** (`*Model.ts`) that turn API records into the prop bags molecules and atoms render (`memeCardModel`, `tradeCardModel`, `questBarModel`, …). Create-meme also keeps its signed upload PUT (`createMemeUpload`) and the video-status poller (`createMemeVideoPoll`) here so `useCreateMemeScreen` stays orchestration-only. Marketplace keeps its URL/query/filter codec (`marketplaceQuery`) here so `useMarketplaceScreen` stays orchestration-only. Tab-scoped sessionStorage is `lib/sessionBus.ts`. Hooks call the builders; components only import their types. |

## Where state lives

| Engine | Holds | Read by |
|---|---|---|
| `stores/authMachine` + `AuthStore` | session: `idle → loading → ready \| unauthenticated \| error`; refresh retains the current user on transient failure | `useAuth`, `useAuthRuntime`, screen hooks |
| `lib/api.ts` | web session credentials: `memeon_session` and `masky_access_token` in `localStorage` (not cookies, not `sessionStorage`). `apiFetch` sends `Authorization: Bearer` and `x-masky-token`. XSS can steal both (HS256 JWT TTL 30d). Logout is this-tab `clearSession()` only — no `storage` event, other tabs stay authed until refresh/401. Agent-browser injects the same keys: `agent-browser --state ./localstorage.json open http://localhost:5173`. | `completeMaskyLogin`, `authMachine`, `apiFetch` |
| `stores/createStores` + `StoresContext` | inert app store bag; committed or imperative owners retain/dispose it | views via hooks |
| `stores/themeStore` + `hooks/useTheme` | preference `auto`/`light`/`dark`, resolved arm, per-avatar persistence; paints `data-theme` on `<html>` | observer views, `ThemeControl` (the public header button, the Settings well), the `AvatarMenu` radio, `SettingsScreen` |
| `stores/*Machine.ts` (one per flow) | XState source of truth for that screen | matching `useXScreen()` |
| `stores/ActorSnapshotProjection` + `hooks/useProjectedActor` | route-local snapshot reference; action-safe MobX updates; XState actor mount lifetime | all stateful screen hooks within `observer` views |
| `hooks/useXScreen.ts` | view-model: projected snapshot + callbacks + derived flags; picks the screen's strings out of `copy/<surface>.ts` (never spells them, never leaves that to the screen) | matching `XView` → `XScreen` |
| `copy/<surface>.ts` | the strings themselves, as data; `copy/shared.ts` for the ones every surface shares | hooks, `lib/*Model.ts`, tests, stories |
| `hooks/useAuth.ts` | `user`, `loading`, `error`, `refresh`, `logout` | `RequireAuth`, chrome, screens |
| `lib/*Model.ts` | pure builders from API records to component prop bags (`buildMemeCardModel`, `buildTradeCardModel`, `buildQuestBarModel`, …); the dialog models carry their `DialogOpenerRef` via `lib/dialogOpener` | screen hooks, stories (fixtures), the components as types only |
| `lib/cardMedia.ts` | the meme card's one imperative seam: a shared IntersectionObserver, `video.play()`, the paused foil ring; exports the stable `cardMediaRef` / `toggleCardMedia` handles the card model hands to `MemeCard` | `lib/memeCardModel` |
| `hooks/useHeroVideo` + `lib/heroVideoModel` | the landing film: whether autoplay is spent (reduced motion, Data Saver, 2g/3g — a live `useSyncExternalStore` probe), started-by-hand, muted; the element is kept for `play()` behind a ref callback so the model stays a plain props bag | `useLandingScreen` → `LandingScreen` → `HeroVideo` |
| `hooks/useMarketplaceCatalog` + `lib/marketplaceQuery` | marketplace catalogue IO: URL codec, 250ms search debounce, cursor paging, IntersectionObserver sentinel, filter/sort URL sync; labels from `copy/marketplace` | `useMarketplaceScreen` → `MarketplaceScreen` |
| `lib/presence.ts` | Firebase online flag; hardcoded web config in `lib/firebase.ts` is expected public client config, not the SSM service account | `useAuthRuntime`, Friends watch |
| `lib/sessionBus.ts` | tab-scoped sessionStorage: `PENDING_VIDEO_KEY` (`/binder/new` remix resume), `INVITE_KEY` (`/invite/:sub` → `/auth/callback`), `POST_LOGIN_KEY` (`/discord/link` → `/auth/callback`), `DISCORD_LINK_KEY` and `DISCORD_LINK_CONSENT_KEY` (`/discord/link`), `MASKY_OAUTH_STATE_KEY` (landing login → `/auth/callback`). JWT (`memeon_session`, `masky_access_token`) remains localStorage in `lib/api.ts`; theme remains `themeStore`. | `useCreateMemeScreen`, `useInviteScreen`, `useAuthCallbackScreen`, `useDiscordLinkScreen`, `lib/auth.ts`, `lib/createMemeVideoPoll.ts` |

`useProjectedActor` uses `useActorRef` to start and stop an actor with its mounted
view. Its side-effect-free projection constructor retains the snapshot by reference
(`observableRef` in MobX 7); `useMountEffect` subscribes, catches up to the current
snapshot, and unsubscribes on cleanup. The view's `observer` reads that projection;
there is no second React snapshot subscription. The component that calls the hook
must be observed, including a keyed child such as `MemeDetailRouteScreen`; observing
only its parent does not track reads in the child. Machines and initial inputs stay
stable for a mount. Entity changes use route keys; route drafts never enter the
global store bag. Actor startup/disposal and projection subscription are separate
lifetimes, including StrictMode's setup/cleanup replay.

The app auth bag has its own ownership lifetime. `createStores()` and the
`AuthStore` constructor neither start nor subscribe. `main.tsx` builds the one
app bag at module level and applies the persisted theme before the first
render; `Root` and Storybook's `FreshStores` retain the bag on committed
mount; imperative scenarios and story setup retain before use. The first `retain()` connects the MobX projection,
catches up inside an action, then starts the actor. A child `useAuthRuntime`
can queue its initial refresh before the parent's retain; the actor processes
that event on startup. Retaining an idle story bag alone does not fetch auth.
Repeated retains cancel deferred disposal without adding owners or subscriptions.
Only a winning disposal microtask disconnects and stops, so StrictMode can reuse
the committed bag while discarded or suspended renders acquire no resources.
A fully disposed bag is finished; imperative scenarios log out before disposal
to settle any pending refresh.

## Making a change

Where each kind of request lands. Most touch two files plus a story; none should
touch four.

| You want to… | Edit | Then |
|---|---|---|
| Change copy (a title, caption, button label, error string) | `copy/<surface>.ts` — the one place the string is spelled | nothing: the builder, its unit test and the story `play` all read the same constant. If a surface still spells its strings inline (see `scripts/copy-baseline.json`), move them into `copy/` first and run `pnpm --filter web run check-copy -- --update` |
| Add a string | a role-named key in `copy/<surface>.ts` (a function when it takes a value: `name: (n) => …`); reuse `copy/shared.ts` for a label another surface already has | the builder picks it, the story asserts through it — never by respelling. A story that overrides one part of the model spreads the built model: `{ ...model.connections, rows: […] }` |
| Change how something looks, set a length, change a token | Tokens: `web/src/index.css` `@theme`. Appearance: the component's `cva` variants. What is allowed: `web/.oxlintrc.json` (`@shadcn/lint`) — run `pnpm --filter web run lint:ds`. | `pnpm --filter web run check-contrast` for a colour, `pnpm --filter web run check-tokens` for a token |
| Pause off-screen foil / start card video | `lib/cardMedia.ts` — shared IntersectionObserver (rootMargin: '200px'), `video.play()`/pause(), inline `--glow-play-state`. `atoms/foil.css` only declares and reads the property. `MemeCard` molecule (`molecules/meme-card.tsx`) only applies `model.cardRef` (`cardMediaRef`) and `{...model.media.toggleProps}` (`toggleCardMedia`). Do not construct an observer in the card; do not wrap it in `useMountEffect` or a view hook. Leave marketplace sentinel in `useMarketplaceCatalog.ts` (rootMargin: '900px'). Do not merge `useHeroVideo`. | `pnpm --filter web run check-card-media`. Keep `applyCardVisibility` as the testable unit (`lib/cardMedia.runtime.test.tsx`). Stories `Video` and `VideoReducedMotion` stay under Molecules/MemeCard. |
| Add a state a screen can be in | the machine in `stores/`, the derived flags in the hook, a **Screen story** for the new state first | the view story that reaches it through the connected scenario |
| Add a new component | its tier folder, pure props → markup, `data-slot` on the root, a sibling `*.stories.tsx` | `pnpm --filter web run check-tiers` |
| Add a shadcn / registry primitive | from web/, `pnpm dlx shadcn add <item>` (never init, never npx) | `scripts/shadcn-postadd.mjs` (`node scripts/shadcn-postadd.mjs`). Registry files import stock cn; this app's merge is `lib/cn.ts` (`createCn` with the material class group and container `card-narrow`). A second copy typechecks and skips the merge. |
| Add a route | a `use*Screen` hook + `*Screen` + `*View` (+ stories), then a `<Route>` in `views/AppView.tsx` (`lazy()` if it is behind `RequireAuth`) | `useDocumentTitle` in the view |
| Persist a value across a route change (OAuth, invite, Discord link, remix-video resume) | `lib/sessionBus.ts` | the caller that reads or writes that key |
| Change what the API returns | `lib/types.ts`, the machine that fetches it, the builder that reads it | `.storybook/fixtures.ts` and `msw-handlers.ts` / `connected-scenario.ts` |

`pnpm run check` is the whole gate (`lint:ds` first, then docs, tiers, copy, card-media, contrast, tokens,
the script tests, proxy, unit, runtime, stories). `check-copy` is a ratchet: it counts copy-like literals still spelled in `hooks/`,
`screens/`, and the `lib/*Model.ts` builders against `scripts/copy-baseline.json`, and a file
may only match or fall below its number (`--list` names the strings, `--update` locks a drop in;
it refuses to raise anything). `pnpm run storybook` (port 6006, MSW-backed) is where a state is verified.

## Rules

- Below Views, no state hooks (`useState` / `useReducer` / `useEffect` / `useLayoutEffect` /
  `useContext` / `useSyncExternalStore`) and no state library. `useRef` is allowed only as an
  imperative handle to a primitive that component composes — today that is `QuestBar` closing the
  Base UI popover via `actionsRef` before the pack dialog (`molecules/quest-bar.tsx`). Do not add
  `useMemo` / `useCallback` / `useId` below views even though `scripts/check-tiers.mjs` does not
  yet ban them.
- The model type is exported by the hook, not the screen.
- A new state starts as a Screen story.
- Every component has a sibling `*.stories.tsx` titled `"<Tier>/<Name>"`.
- Views opt out of autodocs (`!autodocs`) and wrap with `MemoryRouter`.
- Do not put `observer` or `useState` below `views/`.
- Model builders live in `lib/*Model.ts`, not in a tier folder: hooks call them, stories use them
  as fixtures, and a component imports only the model's *type*.
- Strings live in `copy/`, spelled once. Builders read them; tests and stories assert through the
  constant. No tier imports `copy/`, and `copy/` imports nothing but `copy/`, `lib/plural` and
  `lib/braincells`.
- Presentation is Tailwind utilities on the component, in `@layer utilities`. Only effects no
  utility can express get a co-located `.css` file — today the card foil (`atoms/foil.css`,
  side-effect owned by `atoms/foil-frame.tsx`), the spinner turn (`atoms/spinner.css`), the landing
  frame-slot shimmer (`screens/LandingScreen.css`) and the shell's `--topbar-h` rule
  (`organisms/app-shell.css`) — and each restates the layer order at the top.
  The cascade contract itself is the header comment of `src/index.css`.
- Shared code (`shared/tiers.ts`) is imported as `@memeon/shared/tiers`, never by relative path.

## Checker exceptions

The checker recursively classifies every `src/**/*.tsx` and `src/**/*.jsx`
file other than stories and tests. Components in a tier need a sibling story;
components elsewhere fail unless their exact source-relative path is listed
below. This is an allowlist, not a folder exemption: a new `.tsx` file beside
one of these paths must join a tier. JSX-free `.ts` domain modules outside
the tiers remain outside the checker, except `hooks/**/*.ts` and
`lib/**/*Model.ts` (stories and tests skipped; a `.tsx` in those folders still
fails as a component outside a tier). `scripts/check-tiers.mjs` walks
`hooks/useTradesScreen.ts` and `lib/confirmDialogModel.ts` (and every other
file of those shapes) and fails a value import of `createElement` or
`Fragment` from `react`, `React.createElement` / `jsxs`, JSX, or a value
import from `atoms/` / `molecules/` / `organisms/` / `screens/` / `views/`.
Type-only imports stay legal. `document.createElement` is not this rule, and
the walk does not cover all of `lib/` (`lib/createMemeModel/shared.ts` still
value-imports foil). STATE_HOOKS and the copy-import ban do not apply to
hooks. Tier-local `.ts` helpers are checked for state and import boundaries
