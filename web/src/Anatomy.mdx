# UI anatomy

Five tiers. Everything below **Views** is a pure function of its props.

`src/` is organized as atoms → molecules → organisms → screens → views.
Everything below `views/` is a pure function of props: no state hooks, no
stores, no fetch. State lives in `hooks/` (one `useXScreen()` per screen,
exporting `XScreenModel`) and `stores/`. Every component has a sibling
`*.stories.tsx` titled `"<Tier>/<Name>"`. Read this file before adding
or moving a component. `pnpm run check-tiers` runs recursively and must pass;
`pnpm run build` runs it before type-checking and Vite.

| Tier | Folder | What lives there | Owns state? |
|---|---|---|---|
| **Atoms** | `src/atoms/` | `Avatar` (`sm`/`header`/`md`/`lg`), `Badge`, `Button` (`pressed`/`aria-pressed` toggle state), `Checkbox`, `EmptyState` (additive `tone`), `Field`, `Fieldset`, `Icon`, `Input` (its `controlChrome` is shared by `Select` and `Textarea`), `MemeCard` (plus `tierFrameClasses` from `foil.ts`, `memeCardSubClasses`; `footer` and `footerRight` slots), `Notice`, `PageContainer`, `PageHead`, `Panel` (+ `PanelHeading`: `intro`/`section` share intro · `card` card-title · `composer` title), `Select`, `Skeleton`, `Spinner`, `Textarea`, `TierChip` | No |
| **Molecules** | `src/molecules/` | `AlertsBell`, `AvatarMenu`, `ConfirmDialog`, `DialogFrame`, `FaqItem`, `GiftDialog`, `HeroVideo`, `QuestBar`, `SideSummary`, `SortChips`, `ThemeControl`, `TradeCard` (`give`/`get`, not `offer`/`ask`) | No |
| **Organisms** | `src/organisms/` | `AppShell` (slots `sidebar` / `contextLine` / `headerEnd` / `quest` / `bottomNav`), `MemeplexPanel` | No |
| **Screens** | `src/screens/` | One model object per route/chrome surface | No |
| **Views** | `src/views/` | Engine wired to screen; `observer` wrap; `AppView` is the route switch | Via hooks |

Beside the tiers, three folders are the engine side:

| Folder | What lives there |
|---|---|
| `src/hooks/` | One `useXScreen()` per screen (exports `XScreenModel`), plus `useAuth`, `useTheme`, `useProjectedActor`, `useDocumentTitle`, `useMountEffect` |
| `src/stores/` | XState machines (`*Machine.ts`), the MobX `AuthStore` / `ThemeStore`, `createStores` + `StoresContext` |
| `src/lib/` | Everything with no React tree: the API client, auth, presence, formatting (`braincells`, `plural`), `cn()`, `FOCUS_RING`, the imperative `cardMedia`, and the **model builders** (`*Model.ts`) that turn API records into the prop bags molecules and atoms render (`memeCardModel`, `tradeCardModel`, `questBarModel`, …). Hooks call the builders; components only import their types. |

The table lists declared machine phases, including transient phases and states
represented only by prop fixtures. In the reachable flows, initial list failures
for Friends, Binder, and Leaderboard retain their existing empty presentation;
Marketplace errors also present as empty. Detail, trades, and developer errors
include mutation failures. A successful creation navigates away from its screen.

signed-in player can reach is a `lazy()` chunk behind `RequireAuth`.

## Where state lives

| Engine | Holds | Read by |
|---|---|---|
| `stores/authMachine` + `AuthStore` | session: `idle → loading → ready \| unauthenticated \| error`; refresh retains the current user on transient failure | `useAuth`, `useAuthRuntime`, screen hooks |
| `stores/createStores` + `StoresContext` | inert app store bag; committed or imperative owners retain/dispose it | views via hooks |
| `stores/themeStore` + `hooks/useTheme` | preference `auto`/`light`/`dark`, resolved arm, per-avatar persistence; paints `data-theme` on `<html>` | observer views, `ThemeControl` (sidebar segmented + header button), `SettingsScreen` |
| `stores/*Machine.ts` (one per flow) | XState source of truth for that screen | matching `useXScreen()` |
| `stores/ActorSnapshotProjection` + `hooks/useProjectedActor` | route-local snapshot reference; action-safe MobX updates; XState actor mount lifetime | all stateful screen hooks within `observer` views |
| `hooks/useXScreen.ts` | view-model: projected snapshot + callbacks + derived flags — and the screen's **copy** (titles, captions, labels are built here, not in the screen) | matching `XView` → `XScreen` |
| `hooks/useAuth.ts` | `user`, `loading`, `error`, `refresh`, `logout` | `RequireAuth`, chrome, screens |
| `lib/*Model.ts` | pure builders from API records to component prop bags (`buildMemeCardModel`, `buildTradeCardModel`, `buildQuestBarModel`, …); the dialog models carry their `DialogOpenerRef` via `lib/dialogOpener` | screen hooks, stories (fixtures), the components as types only |
| `lib/cardMedia.ts` | the meme card's one imperative seam: a shared IntersectionObserver, `video.play()`, the paused foil ring; exports the stable `cardMediaRef` / `toggleCardMedia` handles the card model hands to `MemeCard` | `lib/memeCardModel` |
| `hooks/useHeroVideo` + `lib/heroVideoModel` | the landing film: whether autoplay is spent (reduced motion, Data Saver, 2g/3g — a live `useSyncExternalStore` probe), started-by-hand, muted; the element is kept for `play()` behind a ref callback so the model stays a plain props bag | `useLandingScreen` → `LandingScreen` → `HeroVideo` |
| `lib/presence.ts` | Firebase online flag | `useAuthRuntime`, Friends watch |

`useProjectedActor` uses `useActorRef` to start and stop an actor with its mounted
view. Its side-effect-free projection constructor retains the snapshot by reference
(`observableRef` in MobX 7); `useMountEffect` subscribes, catches up to the current
snapshot, and unsubscribes on cleanup. The view's `observer` reads that projection;
there is no second React snapshot subscription. The component that calls the hook
must be observed, including a keyed child such as `MemeDetailRouteScreen`; observing
only its parent does not track reads in the child. Machines and initial inputs stay
stable for a mount. Entity changes use route keys; route drafts never enter the
global store bag. Actor startup/disposal and projection subscription are separate
lifetimes, including StrictMode's setup/cleanup replay.

The app auth bag has its own ownership lifetime. `createStores()` and the
`AuthStore` constructor neither start nor subscribe. `main.tsx` builds the one
app bag at module level and applies the persisted theme before the first
render; `Root` and Storybook's `FreshStores` retain the bag on committed
mount; imperative scenarios and story setup retain before use. The first `retain()` connects the MobX projection,
catches up inside an action, then starts the actor. A child `useAuthRuntime`
can queue its initial refresh before the parent's retain; the actor processes
that event on startup. Retaining an idle story bag alone does not fetch auth.
Repeated retains cancel deferred disposal without adding owners or subscriptions.
Only a winning disposal microtask disconnects and stops, so StrictMode can reuse
the committed bag while discarded or suspended renders acquire no resources.
A fully disposed bag is finished; imperative scenarios log out before disposal
to settle any pending refresh.

## Making a change

Where each kind of request lands. Most touch two files plus a story; none should
touch four.

| You want to… | Edit | Then |
|---|---|---|
| Change copy (a title, caption, button label, error string) | the `build*Model` / `useXScreen` in `hooks/` (or the `lib/*Model.ts` builder for a card, dialog, chip or rail) | the story fixtures that spell the same copy, and any `play` assertion that reads it |
| Change how something looks | the component in its tier: Tailwind utilities on the element (`cn()` merges them) | if a `@theme` token is new, add it in `index.css` **and** register its namespace in `lib/cn.ts`; run `pnpm run check-contrast` for a colour |
| Add a state a screen can be in | the machine in `stores/`, the derived flags in the hook, a **Screen story** for the new state first | the view story that reaches it through the connected scenario |
| Add a new component | its tier folder, pure props → markup, `data-slot` on the root, a sibling `*.stories.tsx` | `pnpm run check-tiers` |
| Add a route | a `use*Screen` hook + `*Screen` + `*View` (+ stories), then a `<Route>` in `views/AppView.tsx` (`lazy()` if it is behind `RequireAuth`) | `useDocumentTitle` in the view |
| Change what the API returns | `lib/types.ts`, the machine that fetches it, the builder that reads it | `.storybook/fixtures.ts` and `msw-handlers.ts` / `connected-scenario.ts` |
| Change a token (colour, radius, type step, breakpoint) | `index.css` `@theme static` — one place; every arm is a `light-dark()` pair | `pnpm run check-contrast`; `Anatomy/Tokens` in Storybook shows the result |

`pnpm run check` is the whole gate (tiers, contrast, layers, proxy, unit, runtime,
stories). `pnpm run storybook` (port 6006, MSW-backed) is where a state is verified.

## Soft Press additions (mo-263)

Layered onto the tiers and rules above, not a replacement for them:

- `AppShellScreenModel` (the shell's own engine, `hooks/useAppShellScreen.ts`) grew `theme` (a
  `ThemeControlModel`), `avatar` / `identity` / `avatarMenu` (a Base UI `Menu` model behind the
  phone header's account menu: Profile · 🏆 Top Brains · Settings · 🔧 Developers · Log out),
  `alertsBell`, and `questBar`; `navItems` and `bottomNav` each carry an `Icon` name beside the
  legacy emoji slot.
- `TradeCardModel` (`lib/tradeCardModel.ts`) exposes `give` / `get`, not `offer` / `ask` — the
  wells are keyed to the reading ("You give" is always what leaves your binder), never to who
  proposed the trade; `actions` orders `decline` before `accept`.
- `BinderScreenModel` no longer carries `questRail` — the reward rail is the shell's own `QuestBar`,
  rendered on every route (design-gap decision 8: one rail, owned by the shell). `screens/BinderScreen.tsx`
  exports the grid pieces `ProfileScreen`'s binder tab reuses: `binderGridClasses`,
  `binderCardSlotClasses`, `binderCardFooterClasses`; `stores/binderMachine.ts` exports
  `BINDER_PAGE_SIZE` (12, the `SHOW_MORE` step); `stores/leaderboardMachine.ts` exports
  `LEADERBOARD_PAGE_SIZE` (8) the same way.
- `organisms/AppShell.css` keys `--topbar-h` off `:root:has([data-slot='header'])` rather than a
  fixed value: 64px below the shell breakpoint (`2xl`, 900px), 0px at or above it. Shell-wrapping
  stories render with `layout: 'fullscreen'`.
- `lib/focus.ts` exports `FOCUS_RING`, the one focus contract every interactive atom, row and
  menu item composes: 3px `--color-focus` outline at 2px offset, `contrast-more` 4px,
  `forced-colors` `Highlight`. Hand-copied rings are gone; a component that needs a different offset
  overrides after `FOCUS_RING`, never instead of it.
- `hooks/useDocumentTitle.ts` sets `document.title` per route from the view (the hook layer, not the
  screen); `lib/braincells.ts` formats braincell counts (thousands separators, the 🧠 spacing) so
  every screen prints them the same way.
- `QuestBar` lists every quest inline at both widths, as the boards draw the rail; the old
  "N more ▾" disclosure is gone from the model, the hook and the stories.
- The token sheet lives outside the tiers, at `src/Tokens.stories.tsx` (titled `Anatomy/Tokens`):
  every semantic colour, both static ramps, the seven tier chips, the two materials and the type
  ladder, painted from nothing but the utilities `index.css` emits, each swatch probed via
  `data-slot="swatch-<token>"`.
- The two auth hand-off routes (`/auth/callback`, `/auth/mobile`) are one pure `AuthStatusScreen`
  fed by `useAuthCallbackScreen` and `useMobileAuthForwardScreen`; both cross-origin navigations
  (`navigateToAuthorization`, `forwardToDeepLink`) go through `lib/authNavigation.ts`, which
  Storybook aliases to a recorder so the stories can assert the URL instead of leaving the iframe.

## Rules

- Below Views, no hooks and no state library.
- The model type is exported by the hook, not the screen.
- A new state starts as a Screen story.
- Every component has a sibling `*.stories.tsx` titled `"<Tier>/<Name>"`.
- Views opt out of autodocs (`!autodocs`) and wrap with `MemoryRouter`.
- Do not put `observer` or `useState` below `views/`.
- Model builders live in `lib/*Model.ts`, not in a tier folder: hooks call them, stories use them
  as fixtures, and a component imports only the model's *type*.
- Presentation is Tailwind utilities on the component, in `@layer utilities`. Only effects no
  utility can express get a co-located `.css` file — today the card foil (`atoms/foil.css`), the
  skeleton sweep, the spinner, the landing frame-slot shimmer (`screens/LandingScreen.css`) and the
  shell's `--topbar-h` rule (`organisms/AppShell.css`) — and each restates the layer order at the top.
  The cascade contract itself is the header comment of `src/index.css`.
- Shared code (`shared/tiers.ts`) is imported as `@memeon/shared/tiers`, never by relative path.

## Talking about it

Name the tier and the piece: *"the `MemeCard` atom"*, *"the `GiftDialog` molecule"*,
*"the `CreateMemeScreen` › `Error` story"*, *"`useMarketplaceScreen` should hide the grid on empty"*.

## Checker exceptions

The checker recursively classifies every `src/**/*.tsx` and `src/**/*.jsx`
file other than stories and tests. Components in a tier need a sibling story;
components elsewhere fail unless their exact source-relative path is listed
below. This is an allowlist, not a folder exemption: a new `.tsx` file beside
one of these paths must join a tier. JSX-free `.ts` domain modules outside
the tiers remain outside the checker; tier-local `.ts` helpers are checked for
state and import boundaries but do not need stories.

| Path | Why it stays |
|---|---|
| `main.tsx` | Application bootstrap |
| `stores/StoresContext.tsx` | Root store provider |

There is no `pages/`, `components/` or `context/` folder any more; a component
that does not fit a tier is a design question, not a new exception.
